## How this file works

- The comment block above is the machine-readable header read by `tool/behavior-parity` (audited Web tag and commit, domain, ID prefix, scope). Drift against a newer Web checkout is reported per row from `read.fingerprints.json`; run `tool/behavior-parity --web <web checkout> --domain read`.
- Only the domain auditor edits this file. Fix branches never do. The **Audit** column is the auditor's assessment at the audited commit. It is NOT the status: the computed status is `aligned` when a test in `apps/raft_flutter/test` or `packages/*/test` has the row ID in its name (for example `test('[BP-READ-014] clears the badge locally', ...)`), `intended-difference` / `n-a` when this file declares it (Audit column, with the owner decision and date in Notes), and `open` otherwise.
- IDs are stable and never reused. All Web paths are relative to `packages/web/src`; the anchor is `<path>#<symbol>` or `<path>#event:<socket event>`. "Web ref" line numbers are as of the audited commit and drift; the anchor is the key.
- Flutter paths are relative to `apps/raft_flutter/lib/` unless they start with `packages/`. Abbreviations: `WC` = `data/workspace_controller.dart`, `SAU` = `data/source_activity_unread_store.dart`, `SSU` = `data/source_server_unread.dart`, `FT` = `data/followed_threads_store.dart`, `WED` = `data/workspace_entity_directory.dart`, `MTC` = `data/message_task_cache.dart`, `RV` = `features/resource_view.dart`, `CV` = `features/chat_view.dart`, `WV` = `features/workspace_view.dart`, `WVSM` = `features/workspace_view_sidebar_menus.dart`, `SOCKET` = `packages/raft_client/lib/src/client.dart`, `RS` = `packages/raft_sync/lib/src/`.
- Audit values: aligned / missing / differs / intended-difference / in-progress / n-a / unverified.
- Rows marked in-progress are the already-known items: (1) Flutter `markRead` discards the local clear when the user backs out fast, (2) Flutter lacks scroll-to-bottom mark-read and resume re-mark, (3) owner-approved phone deviation: a live append visible at the bottom counts as read without the 1 s activity gate.
- Web facts worth knowing before reading the tables: the Web socket bridge (`store/socketBridge.ts`) registers 40 events (`MAIN_LAYOUT_SOCKET_EVENT_NAMES`) plus `task:*` / `disconnect` in `store/taskRealtimeSync.ts`. Web has NO `message:deleted`, NO typing event and NO user presence event (agent presence only: `agent:activity` / `agent:seen` / `agent:session`, machine status). Web mention/new flags (`mentionFlags`, `newFlags`) come only from the `GET /channels/unread?summary=1` snapshot and read-state projection, never from a live `message:new`.
- Audited raft-flutter commit: `24f189af70bd8a60d20236e92189e8e03c5f06ca` (working tree clean), audit date 2026-10-12.
