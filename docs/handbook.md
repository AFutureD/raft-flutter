# 工作手册（方法论）

Kevin 和所有参与本项目的 Agent（Cindy、Cody、CodexMac、CodexWin 及其子 agent）共享的工作方法。
AGENTS.md 管"这个仓库怎么写代码"，本手册管"我们怎么做事"：哪些做法被证明有效、哪些坑踩过、遇到某类问题先做什么。

**维护规则**
- 每条都来自真实事件：写清"规则 / 为什么（哪次出的问题）/ 怎么做"。没有来源的意见不进手册。
- Cindy 每天的报告里提出"建议写入手册"的条目，Kevin 确认后写入；其他 Agent 也可以在频道里提议。
- 规则过时就删或改，并注明日期和原因。手册保持一屏能扫完一节，细节放链接。
- 开始一个新任务前读一遍相关小节；子 agent 的任务说明里引用相关条目。

---

## 1. 验证：证据决定结论

- **设备问题要设备证据。** 键盘、生命周期、原生插件、播放器这类问题，必须在模拟器或真机复现并验证修复；只有 widget 测试不算。（2026-10-12 键盘留白"修复"合入后真机仍在）
- **交互要真交互。** 假播放器的 widget 测试拦不住"按钮点了没反应""返回动画卡顿""每次重下"。播放器、手势、路由转场、网络行为的改动，需要模拟器上真实点击、录屏和按字节计数的本地服务器。（2026-10-13 系统播放器三处回归）
- **先证明测试能失败。** 新增回归测试要先在旧代码上跑红，再在修复上跑绿；没跑过红的测试在报告里如实写"未验证会失败"。
- **说法要和证据范围一致。** 实验台结果不能说成"用户场景已解决"；模拟器没有 HDR 屏就不能说"HDR 已验证"。报告里明确写"测到了什么、没测到什么"。
- **改正自己说错的话。** 发现之前的结论或数字不准，立刻在原话题里更正，不等别人发现。

## 2. 对齐 Web：四个层面都要看

只对齐"长得像"会漏东西，至少四层：
1. **像素：** 已有页面和 Web 截图逐像素比（`tool/parity-ext`、`docs/parity.md`）。
2. **字段：** 读的数据字段和服务器真实结构一致（`docs/field-parity.md`）。
3. **能力：** Web 能做的每个操作我们能不能做（`docs/capability-parity.md` + 守卫测试）。（2026-10-13 服务器头像上传整块漏掉）
4. **状态：** 每个页面的加载中 / 空 / 出错 / 部分数据状态也要对齐，并进入对比用例。（2026-10-13 Agent 工作空间"加载中"贴边）

上游 Web 每周对比一次（`tool/upstream_sync.py`，`docs/upstream-sync.md`），由 Kevin 逐项决定跟不跟。

## 3. 状态与资源：谁设置谁负责清除

- **临时提示必须绑定原因。** 提示、错误条、横幅跟它的原因绑定（`CauseNotice`），原因不成立就自动消失；新增提示没有消失条件，守卫测试不过。（2026-10-13"请等待上传"永不消失）
- **看不见就释放。** 解码器、帧缓冲、WebView、解码后的图片在离开屏幕、播完、页面隐藏、内存紧张时释放，不依赖组件销毁。（2026-10-13 9 个 4K 帧缓冲约 285MB 不释放）
- **服务器级的东西随服务器生命周期清理。** 删除 / 离开服务器时取消它的进行中请求、清掉它的错误；过期作用域的失败不报给用户。

## 4. 并行协作

- **动手前先看话题。** 没 @ 你的顶层请求，先读它的话题有没有人已经接；对外动作（打 tag、发布、推送共享分支）更要先确认。（2026-10-13 v0.1.0+5 tag 和 CodexWin 撞车）
- **一个人负责一件事的结论。** 谁做的谁汇报；复核方独立给结论（例如 CodexMac 复核播放器），不替对方宣布完成。
- **分工写清边界。** 多个 agent 同时改代码时，任务说明里列出"别碰的文件"；必须改共享文件时只做最小改动并告知。
- **子 agent 默认 Sonnet，最多约 6 个并行；** 子 agent 再拆子任务时也算在内。

## 5. 集成与检查（gate）

- **历史保持线性。** 变基或压缩后快进合入，不产生 merge 提交；不强推 integration / main。
- **每个分支合入前跑一次全量检查**（`tool/prepare-handoff`）；变基后重跑受影响的测试再推送。
- **检查失败要快、要通知。** 编译错误、≥3 个失败、长时间无输出即中止并通知；先区分"代码问题"还是"环境问题"再处理。
- **环境卫生。** `/tmp` 是有配额的内存盘，满了会让测试卡死：中断的测试留下的 `flutter_tools.*` 要清；共享缓存目录的清理要考虑并行进程。（2026-10-12 检查连续卡死；2026-10-13 清缓存引发并行竞态）
- **汇报前扫一遍所有分支**，列出"做完没合入"的工作。（2026-10-12 一个做完的分支被遗漏）

## 6. 和 Kevin 沟通

- 先给结论，再给原因和下一步；中文、完整句子，少用内部术语。
- 需要他决定的事单独列出，给出建议而不是罗列选项。
- 涉及密钥的事情让他本人操作，我们只拿公钥或结果，不经手私钥和登录凭证。
- 每天中午 12 点（东京时间）发日报：工作、观察、外部调研、1–3 条改进建议，并附"建议写入手册"的条目。
