# Activity 按条目身份识别双击

连续点 A、B 曾被当成双击，打开 A 的完整页面。修复把双击判断绑定到条目身份；系统时间窗内点 B 立即切换到 B 的预览并重新计时，再点 B 才打开 B。首次预览立即选择，未选中时仍为全宽列表。

依据：Kevin 实际使用反馈，Cindy 在 Raft 消息 `9055206b-6c25-4b19-a5e7-5b1c70ca1613` 撤销此前跨行规则。条目身份使用现有 `rowKey` / `activityItemKey`，包含条目类型和 id，不以屏幕位置或相同标题替代。

## 行为

| 输入 | 结果 |
| --- | --- |
| A→A，仍在系统时间窗内 | 使用 A 首次点击的原始未读/提及焦点打开 A，增加一次完整页面历史 |
| A→B，仍在 A 时间窗内 | 立即预览 B，不增加完整页面历史，开始 B 的新时间窗 |
| A→B→B，第三下超过 A 旧时间窗、仍在 B 新时间窗内 | 打开 B，增加一次完整页面历史 |
| 点列表空白 | 结束当前双击识别，不打开完整页面 |
| 详情、工具栏、键盘或语义操作 | 使用各自普通操作，不续接指针双击 |
| 时间窗结束、筛选/权限/账号/服务器/导航变化 | 清理对应手势，不接受过期升级 |

Unread 读取仍立即清掉徽章。切换到另一行并重新计时时，沿用当前可见顺序和已测行高度，防止前一条已读行收起后挪走新条目的第二次点击位置。识别结束后正常更新未读列表。无详情时的 N27 全宽/无详情容器断言保留。

## 验证边界

测试使用实际 WorkspaceView / ResourceView 与隔离的本地请求，不使用独立模拟导航器。三个主题分别在全宽→分栏后点击另一行，立即检查 B 预览、焦点和历史；再过 350ms 点击 B，验证新时间窗和 B 的完整页面。另有实际 Unread 点击验证 B 的矩形不变、首次未读/提及焦点，以及列表空白不升级。

定向回归在未修改产品的 `7df31753de7456eade906fd40b48dc2b1eb3d8fb` 上出现 9 个失败、12 个通过；修复后全部 21 个通过。35 个相关文件共 438 个测试通过；去掉旧跨行规则在测试中加入的等待后，另跑 33 个快速切换/晚到响应回归通过。根静态分析无问题，设计系统检查无增长，baseline/allow 规则未改。初次失败日志与最终检查均保留于证据包。
